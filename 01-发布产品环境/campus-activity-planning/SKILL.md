# 校园活动策划案撰写与格式处理

这是一个对外使用的统一 Skill。它按用户任务和当前对话进度，在策划内容模块与 Word 格式模块之间分流。每次回复都简要标明当前阶段和需要用户确认的事项。

## 阶段路由

1. 用户提出新活动、需要策划案或只给出初步活动信息时，进入“框架设计”。读取[业务交互流程](references/workflow.md)、[框架设计研究](references/knowledge/framework-design-research.md)和[内容颗粒度](references/knowledge/content-granularity.md)；按活动事项读取[活动经验](references/knowledge/activity-experience.md)。提交框架后等待用户确认。
2. 用户确认框架后，进入“逐模块填写”。按一级标题逐项询问、整理和确认；一次口述牵涉多个模块时，当轮按约定展示主模块和受影响模块。模块作为主模块时仍需专门询问。
3. 所有模块均完成专门询问和确认后，进入“全文确认”。先在对话框展示完整、易读的全文，等待用户确认。只有用户确认全文后，才能生成 Markdown 交接稿。
4. 全文已确认且用户要求排版，或用户直接提供符合交接规范的已定稿 Markdown 并要求生成 Word 时，进入“格式处理”。先读取[格式模块说明](references/formatting/format-workflow.md)、[输入契约](references/formatting/input-contract.md)和[格式规则](references/formatting/format-rules.md)。

用户只要求某一阶段时，完成该阶段要求的范围。用户已有完整内容时，可从相应阶段开始，不要求重复走完前序阶段；仍需确认该内容是否已定稿，才能进入 Word 格式处理。

## 事实和内容边界

- 以用户提供的本次活动信息为事实来源。历史案例用于校准结构与颗粒度，不将案例中的日期、人员、数字、价格或规则直接当作本次事实。
- 内容整理忠实保留用户表达，只做必要的语言规范化；遇到会影响原意的歧义时，向用户澄清，不自行补写。
- 一级标题组织主要业务方面，二级标题展开相对独立的重要活动或工作环节。执行细节按需要放入正文、条目或表格，不为增加标题而细分。
- 活动背景、目的、时间、地点和参与对象等含义清楚的标题不加注释。工作安排、材料等宽泛标题仅在短说明确实有帮助时提供内容方向。
- 公开包不含原始策划案、通知、工作手册和个人信息。来源及适用边界见[知识来源索引](references/knowledge/sources.md)与[注意事项](references/knowledge/cautions.md)。

## Word 格式处理边界

格式模块保留原稿内容，执行输入检查、Word 生成和机器核验。它依赖 Windows、Microsoft Word 和配置中列明的字体。若当前环境无法使用这些依赖，完成内容协作和 Markdown 交接，并明确说明 Word 文件需在具备环境的电脑上生成；不得声称已完成 Word 验收。

格式脚本位于 `scripts/`。运行规则、依赖和输入限制见上述格式模块说明及参考文件。
