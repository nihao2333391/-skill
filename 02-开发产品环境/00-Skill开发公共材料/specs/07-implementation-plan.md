# 07 SDD 研发里程碑与交付门槛

## M0：资料核查和知识建模（当前起点）

- 输入：两份 PDF + 本包需求。
- 任务：提取案例能证明的章节和颗粒度；提取格式明文规定；记录暂不能确定的组织规范。
- 产物：修订版 `02-case-to-knowledge.md`、用例证据清单、开放问题。
- Gate：来源明确/归纳/待确认三类信息区分清楚。

## M1：活动信息→适配框架的原型（第一个可用成果）

- 输入：用户自然语言活动任务、可选补充资料。
- 任务：识别目标/事项/约束→补全分析维度→按范式提出一二级标题与内容方向。
- 产物：第一阶段 Skill 指令/知识文件、3 个以上可复现实例、验收记录。
- Gate：T01—T07 通过，用户确认框架质量和阅读体验。

## M2：对话填写与文章成稿

- 任务：用户确认框架后逐个一级标题专门询问和确认；同一轮口述牵涉其他模块时，在主模块之后展示相关模块内容供确认，但之后仍专门询问这些模块；忠实整理用户口述，不臆想扩写；全部模块确认后展示便于阅读的完整稿并等待用户确认，再按共同约定生成 Markdown 交接稿。
- 产物：可复用写作 Skill、文章示例、变更测试记录。
- Gate：T08—T10 通过。

## M3：写作到排版的语义接口

- 任务：使用已确认的真实文章，对比两个最轻量的接口候选（例如可读 Markdown 层级与内部结构对象），测试内容/层级/顺序保真；决定是否需专门存档。
- 产物：接口契约、输入示例、自动/人工保真校验。
- Gate：T11—T12 通过；用户无需接触机器结构。

## M4：排版引擎

- 任务：将参数配置与处理程序分离，DOCX 生成、样式验证、排版异常报告、字体降级提示。
- 产物：通用格式化 Skill 的程序/配置/测试输出。
- Gate：T13—T14 通过；在指定运行环境中稳定。

## M5：跨宿主封装和实际部署

- 任务：创建清晰的 `SKILL.md`、references/assets/scripts 的组织方式；在 Codex 及另一个目标 AI 宿主上测试。
- 产物：可安装/复用的 Skill 包、宿主能力矩阵、演示文稿。
- Gate：T15 通过并说明支持范围。

## 实施原则

每个里程碑执行：**需求 → 设计 → 小任务 → 测试 → 审核 → 下一里程碑**。先提交可读可测的成果，再决定下一步技术细节。用用户可感知的质量（是否覆盖关键业务、是否省去反复修改）评估收益。
