# 策划案知识来源索引

归档日期：2026-10-08。用途：为未来写作 Skill 提供可追溯的案例依据。

本目录是知识参考材料。条目中的“Skill 使用方式”属于后续实现建议；归档本身不代表 Skill 已实现。当前工作依据用户确认的顺序：预先学习策划知识 → 接收本次任务信息 → 分析业务并生成适配框架 → 用户确认后逐步成稿。

## 信息状态

- **来源明确**：文档中能够定位到的内容。仅证明该文档写了什么，其适用范围随文档和活动而定。
- **工作归纳**：从案例推导出的可迁移经验。使用时须检查本次活动是否满足适用条件。
- **需要确认**：材料之间有矛盾，或现有资料不足以决定的事项。保留缺口，交由本次任务信息或用户确认补齐。

知识条目中使用 S01—S08 引用下表；PDF 按文件页序定位，DOCX 按章节标题和表格定位，避免依赖随查看器变化的页码。

## 未来 Skill 的读取方式

1. 生成提纲时，读取[内容颗粒度](content-granularity.md)，决定标题与正文怎样组织。
2. 根据本次业务事项，选择[活动经验](activity-experience.md)中的相关条目；同一活动可结合多条经验。
3. 生成或修订内容时，应用[注意事项](cautions.md)中的事实、来源和冲突处理规则。
4. 遇到适用范围不清、材料冲突或原件更新时，通过本索引回看原始位置。

5. 决定一级、二级标题以及怎样避免过度细分时，阅读[框架设计逻辑研究](framework-design-research.md)。

后续创建 `SKILL.md` 时，可将必要的工作流程写入入口，将这些材料作为按需读取的 references。这里记录的是组织建议；当前文件夹继续承担知识归档用途。

## 后续维护

新增经验先补来源编号和具体位置，再写适用条件、处理建议和待补信息。新增案例支持或推翻既有归纳时，更新原条目的范围。历史样本中的具体数据与可迁移规律分别记录；疑点集中保留在注意事项的疑点表中。
