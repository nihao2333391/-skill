# 高校校园活动策划案框架设计逻辑研究

研究日期：2026-10-10  
研究目的：为后续策划案写作 Skill 建立有材料依据的框架设计方法。  
核心问题：面对一项新的校园活动任务，如何决定策划案写什么、为什么写、按什么结构写、写到什么程度？

## 核心结论

策划案框架不是把常见标题排成目录。策划人员先要从活动目标、要完成的工作和实施条件判断本次活动的主要信息层，再用一级标题组织主要业务方面，用二级标题展开其中相对独立的重要活动或工作环节。随后把具体步骤、人员、时间、物资、风险和交付放进合适的正文或表格。

历史策划案提供两类依据：一类是同类活动反复出现的高层结构；另一类是某个活动类型特有的组织要点。使用时需要连同标题下的正文一起读，才能知道标题为什么存在。标题相似只能提示进一步比较，不能单独证明业务相同。

本研究将原文能够定位的信息标为**来源事实**，从案例推导的规律标为**案例归纳**，需要组织或用户补充的内容标为**待确认**。具体标题层级以原件可见编号和文档组织为依据；对没有清晰编号的 Word 小节，按其在正文中的内容结构描述，不把它们冒称为规范编号或 Word 标题样式。

## 二、典型案例：活动需求怎样形成章节

### 案例 A：项目化志愿者招新策划案

**材料**：[2026—2027 学年项目化志愿者招新活动策划案](../原始案例材料/2026-2027_志愿者招新活动策划案.pdf)，第 1—3 页。案例目标包括宣传学生会、招募志愿者和收集报名信息；实际安排包括线上通知、校区点位、接收报名表、材料汇总和后续遴选。

| 原件一级标题 | 需求或任务依据 | 章节解决的问题 | 层级判断 |
|---|---|---|---|
| 一、活动背景 | 说明组织工作背景与开展招新的原因 | 让审批和执行人员理解活动从何而来 | 解释活动背景的高层信息 |
| 二、活动目的 | 宣传、招募、完成报名收集和后续遴选准备 | 说明期望达成的结果 | 目标被单列；不能据此推定所有策划案都必须把背景、目的分开 |
| 三、活动时间 | 招新跨多个日期，且每日有具体时段 | 让参与者和工作人员掌握开展时间 | 时间范围本身影响参与与排班 |
| 四、活动地点 | 两个校区设固定点位 | 使报名者能找到提交点，也支持岗位布置 | 多点位条件使地点具有独立说明价值 |
| 五、参与人员 | 有负责人及明确招新对象 | 确认工作责任和参与范围 | 对象及负责人影响通知、岗位与招募边界 |
| 六、工作安排 | 需要完成通知、点位招新、报名汇总 | 让多个业务环节按先后衔接 | 主业务流程的一级组织标题 |
| （一）线上通知 | 需告知地点、截止时间和填写要求 | 让意向同学知道如何进入报名流程 | 独立渠道及信息告知环节 |
| （二）点位招新 | 设点宣传、介绍工作、引导入群、接收纸表 | 组织报名者到场，并完成现场收件 | 独立现场环节，含多项操作条目 |
| （三）材料汇总 | 活动结束后清点、登记、归档和移交 | 保证收集到的报名资料进入后续遴选流程 | 由活动后交付需求产生的独立环节 |
| 七、所需材料 | 宣传、报名、辅助物资各有用途 | 支持不同岗位完成宣传和收件 | 资源清单集中呈现，便于筹备 |
| 八、工作注意事项 | 需按时到岗、保护报名信息、管理物资并处理突发情况 | 处理该活动实际风险与执行要求 | 风险是由报名资料和现场执行带来的；不能只凭习惯机械添加 |
| 九、后续工作说明 | 报名材料汇总后将进入遴选 | 交代本次工作结束后的去向 | 活动产出需要交接，因此单独说明 |

**案例归纳：**招新内容存在从触达、现场参与、收集信息到后续使用的连续流程。三个二级标题代表业务渠道/环节；报名表数量核对、保管方式等细节在“点位招新”内部用条目说明。材料保密和归档能够回溯到实际报名信息流转。

### 案例 B：教师节主题活动策划案

**材料**：[2026 年教师节策划案](../原始案例材料/2026年教师节策划案.pdf)，第 1—3 页。原件活动为“我和老师的 100 个故事”相关领取、教师节倡议书展示、书写祝福并领取纪念品。它与 examples 中“献花、现场答题”的假设任务不同。

| 原件结构 | 需求或任务依据 | 章节解决的问题 |
|---|---|---|
| 一、活动背景及目的 | 围绕教师节主题开展尊师重教宣传与参与活动 | 在同一部分说明背景和预期效果，减少拆分后的重复 |
| 二、活动主题 | 活动具有统一主题名称 | 给多个并列内容提供共同主题 |
| 三、活动对象 | 面向全体全日制在校生 | 确定活动参与范围 |
| 四、主办单位；五、承办单位 | 共同组织单位与具体承办方均需出现 | 区分组织责任来源；属于该文稿的组织信息安排 |
| 六、活动时间；七、活动地点 | 两校区各有场地；领取活动还区分集中领取和补领时段 | 支持参与者选择时间地点，也支持两校区现场部署 |
| 八、活动内容及具体安排 | 三项主题活动的参与方式、物品和地点不同 | 将总流程下的多种参与机制分别呈现 |
| （一）我和老师的 100 个故事 | 前期征集、评选，入围作者领取纪念品 | 交代活动前期工作与当天核对、发放之间的关系 |
| （二）教师节倡议书 | 展板展示倡议内容 | 说明无需报名、以现场阅读为主的展示形式 |
| （三）送给老师的 100 个祝福 | 领取纸笔、书写、交给工作人员张贴、领取纪念品 | 交代参与动作及其完成后果 |
| 九、人员安排 | 现场核对、发放、收集、秩序维护及补领工作分时段进行 | 把岗位工作与不同活动及时间段对应起来 |
| 十、活动预算 | 多类物品有数量和单价 | 汇总活动所需经费，支持采购与审核 |

**案例归纳：**共享主题不代表应把所有环节合成一个二级标题；当不同活动的参与方式和岗位操作不同，分项更易执行。背景与目的可合并，说明标题层级应从信息作用决定，而非照搬另一案例。

### 案例 C：2024 与 2025 年国庆主题升旗仪式策划案

**材料**：[2024 年升旗仪式策划案](../原始案例材料/2024年东北大学国庆节主题升旗仪式策划案.docx)和[2025 年升旗仪式策划案](../原始案例材料/2025年东北大学国庆节主题升旗仪式策划案【终版】.docx)。两份正文均围绕活动背景、目的、主题、对象、组织单位、时间、形式、升旗仪式安排、队伍要求、活动流程和预算展开。正文编号并不完全统一；以下按可见结构归类。

| 内容层 | 活动需求或任务 | 章节/内容承担的作用 | 两年间表现 |
|---|---|---|---|
| 背景、目的、主题 | 纪念节点与仪式教育目标 | 说明举办缘由、活动效果和本届主题 | 主题内容变化；背景目的段落随年份改写 |
| 对象、主办、承办 | 各学院学生代表和学生组织参与，团委与学生会承担组织角色 | 说明参加范围及组织责任 | 主要结构保持稳定 |
| 时间、形式、场地测量 | 两校区同时开展，场地容量不同 | 支持人员到场安排及空间规划 | 场地和名额按活动实际条件列出 |
| 材料物品准备、人员安排 | 需准备音响、音乐、旗帜、稿件，并安排主持、摄影、发言代表等 | 保证仪式角色与设备到位 | 具体内容随执行配置使用 |
| 学院队伍相关要求 | 各单位按名额组织队伍、按时到场，设置领队和站位 | 让外部参与队伍能按统一要求进入仪式 | 同类活动中稳定出现；具体截止日期、人数有年度差异 |
| 活动流程 | 工作人员先布置，代表队入场，仪式开始，最后恢复场地 | 把筹备、入场、仪式和收尾按时间组织 | 流程框架近似，日期、时刻及当年主题变化 |
| 活动预算 | 展板、音响等场地物资产生费用 | 提供采购与经费信息 | 具体项目和金额属于单次事实 |

原件中“场地测量、材料物品准备、人员安排、队伍要求、活动流程”以无编号的内容小节出现，分属于“升旗仪式活动安排”等部分。**案例归纳：**两份同类案例支持“仪式流程与队伍组织是重要信息层”的判断；它们不能证明这套结构适用于普通互动活动。附件中的站位图、名单等未在本研究中逐张核验。

### 案例 D：2026 年迎新活动策划案与迎新工作手册

**材料**：[2026 年迎新活动策划案](../原始案例材料/2026东北大学迎新活动策划案.docx)及[迎新工作手册](../原始案例材料/迎新工作手册.pdf)，手册第 1—2 页。

| 策划案标题/手册内容 | 活动需求或任务 | 章节作用与颗粒度 |
|---|---|---|
| 策划案：一至七、活动目的、主题、对象、主办、承办、时间、地点 | 向新生介绍学生组织，活动涉及两校区 | 交代活动方向、责任和开展条件；呈现为前置基础信息 |
| 八、准备工作；（一）前期安排 | 招募工作人员、制作物料、培训、布置场地 | 按筹备时间说明依赖事项和完成节点 |
| （二）当天工作及人员安排 | 四个帐篷设置坐班、引导、宣讲/机动岗位；班次、错峰宣讲、交接和午间保障 | 用表格和条目明确岗位协作与轮班细节；这是执行复杂度较高的部分 |
| 九、活动具体内容；（一）成果展示区；（二）互动打卡区 | 介绍学生组织、设置打卡和拍照互动 | 两类参与方式不同，分为二级标题；可选展板方案和打卡机制再放入子项 |
| 十、物资及预算 | 有易拉宝或桁架备选方案，以及设备、相纸等费用 | 支持方案选择、采购和预算对照；金额应与所选方案及统计范围一致 |
| 十一、应急预案 | 户外活动可能遇到天气和现场人员变化 | 写出与场地、人员直接相关的应对安排 |
| 手册：工作总则、人员分工及要求、整体流程、具体工作筹备、应急预案处理 | 给工作人员提供当天操作指导 | 更偏执行手册；详细工作步骤和应急替代方法适合操作资料，不必全变成对外策划案的标题 |

**需要确认的类型边界：**工作手册明确区分迎新和招新，侧重组织介绍；2026 年迎新策划案的活动目的同时写到“发掘并吸纳”新生骨干。材料可能反映当年活动把介绍与招募结合，也可能存在口径差异。未来遇到迎新任务，应先依据用户说的目标和具体机制判断，必要时确认活动是否同时包含招募。

**案例归纳：**当岗位、时段、多个展区和备选方案同时存在时，框架与正文可以更细；复杂度来自工作协作关系，而不是“迎新”这一名称本身。原件的班组名称、人数口径和预算范围有不一致，详见[注意事项](cautions.md#n03-保留案例疑点及其影响)，不作为可复用默认值。

### 案例 E：校园接力跑活动通知

**材料**：[校园接力跑活动通知](../原始案例材料/关于举办东北大学纪念“一二九”运动90周年校园接力跑活动的通知.pdf)，第 1—3 页。它是面向学院的活动通知，不是同类完整策划案，适合作为策划外部约束的材料。

| 通知部分 | 执行需求 | 对策划框架的参考作用 |
|---|---|---|
| 活动时间、地点 | 两校区设起点、路线不同 | 提醒策划者区分校区路线和集合地点 |
| 报名要求 | 各学院推选队员、填写名单并按时提交 | 形成参与名额、责任单位、材料和截止时间等明确约束 |
| 活动安排 | 集合、出发、回到起点、宣布结果和颁奖 | 供内部策划按时间补充路线、岗位和现场执行细节 |
| 奖项设置 | 按校区评奖和成绩排名 | 需在内部方案说明计分、评定和颁发的执行办法；通知未说明的机制不能推定 |
| 注意事项 | 动员、队伍管理、领队调度、路线和运动安全 | 将真实参与条件带入相应章节，细化保障措施 |

**案例归纳：**外部通知能提供任务约束和对参与单位的要求，内部策划还需补足执行分工和工作流程。两类文件服务对象不同，章节不能机械合并。

## 三、跨案例框架规律

| 信息层/策划关切 | 案例依据 | 稳定程度 | 框架处理原则 |
|---|---|---|---|
| 为什么做、希望达成什么 | 五份活动策划案均有目的相关内容，但标题有背景与目的分列、合并或未编号等差别 | 业务关切稳定，标题组合可变 | 保留活动依据和预期作用；背景短且不需单独说明时可合并 |
| 谁参加、谁组织 | 招新、教师节、升旗和迎新案例都有参与对象与组织责任信息 | 常见，标题是否单列可变 | 当对象、主办承办、责任关系影响通知或审批时明确表达；简短信息可合并在基础信息中 |
| 什么时候、在哪里 | 五份策划案和接力跑通知都有时间地点；多校区案例分别列明 | 信息通常重要，表达可分可合 | 多时段、多校区、多个路线影响实际执行时分开说明；单地点单时段可合并 |
| 做哪些活动或工作 | 招新、教师节、迎新和仪式均有主内容安排 | 核心信息层 | 一级标题组织主要业务板块；不同流程、参加方式或责任独立的内容再展开二级标题 |
| 怎样准备和分工 | 迎新、升旗、教师节等安排了前期准备、现场岗位或人员安排 | 随执行复杂度增减 | 有明确依赖或多人协作时单列；简单活动可与活动安排合写 |
| 需要哪些物资和经费 | 多份活动方案有物资或预算内容；活动通知未形成预算章节 | 有资源需求时纳入 | 按需单列物资/预算；多个校区、备选方案或需审批时以表格说明 |
| 有哪些风险与执行要求 | 招新关注资料保管，户外迎新关注天气和空岗，接力跑关注路线和运动安全 | 活动特性决定具体内容 | 从活动条件和后果推导注意事项；不把通用“应急预案”作为无条件固定标题 |
| 活动后有什么交接 | 招新归档并进入遴选，迎新回收设备，仪式恢复场地 | 有产出或借用资源时重要 | 识别成果、资料、设备、剩余物品的接收方；简单活动可用一段话说明 |

### 一级标题表达什么

**案例归纳：**一级标题把较高层的信息维度放在一起，使读者能回答活动“为何举办、面向谁、由谁组织、包含哪些主要工作、如何保障”。它不应跟随每一个时间点、物品或动作逐条新增。一个一级部分可以容纳多个相互关联的内容项。

### 二级标题表达什么

**案例归纳：**二级标题主要展开主要活动板块或需要分别组织的工作环节。例如招新的线上通知、点位招新、材料汇总；教师节的故事领取、倡议展示和祝福互动。若一个小项只有一句共同规则，或是某个环节中的单一步骤，通常放在正文或编号条目更合适。

### 正文、条目和表格表达什么

**案例归纳：**正文用于说明目的、方式和关系；编号条目用于列出一个环节的操作步骤和要求；表格用于对照岗位、时段、物资、数量或经费。层级越低，内容越具体。把细节放在合适的载体中，避免把目录写成工作清单。

## 四、新活动框架设计方法

本方法面向“从顶至下组织信息层级”的策划方式。先确定要表达的主要业务维度，再在维度下安排关键活动或工作环节，最后补执行细节。

### 第一步：把任务信息分成目标、事项、条件与状态

记录用户想实现的结果、已经提出的活动事项、影响组织执行的约束，以及信息是已确定、暂定建议还是未知。用户给的事项描述活动做什么；约束描述这件事在哪里、对谁、在什么范围内开展。两者共同决定框架。

**作用：**避免把目标误当成活动流程，也避免把假设当成事实。若用户提到上级明确要求的内容，将其标为本次约束，在框架中留出表达位置。

### 第二步：识别活动类型与可改变结构的特征

从具体机制识别特征，而不是只按“迎新”“纪念日”等活动名称套模板。检查活动是否涉及多校区或多点位、队伍集合或路线、报名与个人信息、多个并行互动、资格核验或奖品发放、轮班交接、预算备选、成果或设备回收等。

**作用：**这些特征会增加真实的组织和执行工作，能解释为什么某些信息应进入框架。例如，多校区影响场地和人员安排；报名信息流转影响收集、保管与交接；户外路线活动影响集合、领队和安全内容。

### 第三步：由业务需要推导候选信息层

围绕活动提出策划案要回答的问题：活动依据和目标是什么？参加对象与组织职责是什么？主要业务内容由哪些板块组成？各板块有什么执行流程、资源或约束？存在什么具体风险？产出和物资交给谁？这些是候选信息维度，尚不是固定标题。

**作用：**用问题检查业务是否有遗漏，同时不给每个维度预留一个必然独立的一级标题。可把相关维度合并在同一较高信息层中。

### 第四步：先决定一级标题所表达的高维信息

把候选维度与本次目标和主要工作对应。一级标题应组织重要业务方面，承担相对完整的说明任务，并帮助审批者和执行者找到策划案的主要内容。判断时问：删去这部分后，活动目标、主要工作、组织条件或关键保障是否变得难以理解？若否，可考虑合并进相关部分。

**作用：**控制整体结构，让读者先看出活动的业务构成。标题是否使用“活动安排”“活动内容”“工作安排”等词，可以参照用户习惯；标题名不等于业务逻辑本身。

### 第五步：仅为重要且相对独立的环节设置二级标题

检查候选事项是否有相对独立的参加方式、执行流程、责任人员或资源安排。多个线索同时存在时，更适合独立展开；若只是同一环节里的一个动作，放在父级的条目中。

**作用：**保留活动内部的重要差异，同时防止把每个动词和细节升格为标题。可用“如果执行人员需要分别组织、解释或安排这个事项，它是否值得单独展开？”辅助判断。

### 第六步：用同类案例校准结构，不复制旧标题

同类案例应同时比较标题和标题下的内容，确认其背后的需求是否也存在于本次任务。保留能帮助理解本次主要业务的结构；对本次不存在的业务，不沿用其专属章节。若没有同类案例，使用前三步推导出的业务问题，再按一般策划写法组织。

**作用：**旧案例校准当地表达习惯、颗粒度和常见安排；本次任务决定是否采用。异类案例可提供局部经验，例如借鉴活动通知中的报名约束或工作手册的岗位交接，但不能整套套用。

### 第七步：把细节放回所属信息层

时间、地点、人数、流程、人员、物资、风险和后续交付，根据实际关系放入对应章节。并列岗位或预算可用表格；顺序动作写为条目；目的、依据和方案逻辑写成正文。预算、场地、规则等尚未确定时，在对应章节标为待补充，避免为每个未知数增设标题。

**作用：**保持标题处于较高信息层，同时让读者能看到各部分需要补什么。只有当某项细节本身形成需要单独组织的业务板块时，才考虑上升为二级标题。

### 第八步：提纲提示跟随框架，而不反过来扩张框架

给每个主要部分写简短内容方向，并列出确实影响该部分执行的待补信息。已知事实直接放入对应章节；建议和未知分别标识。仅当缺失信息会改变活动类型、主要板块或硬性安排时，优先追问。其余细节保留在相应部分后续讨论。

**作用：**让框架既可阅读也能推动后续写作；信息缺口有地方承载，不需要先将其变成新的一级或二级标题。

## 五、标题细化的判断卡

### 值得独立成为一级标题的信号

- 内容是活动目标、主要业务板块、组织职责或重要保障等较高层的信息。
- 该部分有足够内容，且能清楚承担一个完整的阅读目的。
- 与其他部分的职责不同；合并后会让结构难读或令主要业务难以查找。

### 值得成为二级标题的信号

- 它是某个一级业务板块中的重要活动或工作环节。
- 它与相邻事项的参加方式、流程、执行责任或资源安排存在实质差异。
- 单独列出能帮助组织活动、分工或安排阅读。

### 更适合留在正文、条目或表格的信号

- 它是一个独立环节中的单步操作、时间点、物资细目或执行要求。
- 它与父级标题的主旨一致，篇幅不足以形成有意义的独立内容。
- 表格、编号条目或短段落已经能够清晰呈现。

### 防止过细的三问

1. 这项内容对应本次已经提出的目标、事项、硬性要求或有依据的活动特征吗？
2. 它与相邻内容存在需要分别组织的实际差别吗？
3. 放在上一级的正文或条目中，会不会因此难以查找或执行？

如果前两问都不能说明单列理由，先合并处理。若第三问说明步骤很多，再在正文中编号或用表格呈现，不必立即继续拆标题。

## 六、信息不足时怎样先形成结构

**有目标和一项或多项主要事项时：**通常可以先据此形成候选信息层及标题，再将未知事实放入对应部分。举例来说，用户给出“两个校区开展献花和现场答题”，可先识别两个活动板块和多校区这一条件；参与对象、时段、具体规则及岗位人数仍留在对应内容中待补。此为推导示例，不是历史教师节案例的事实。

**目的或主要事项不足以判断活动形态时：**先问少量能改变一级结构的问题。例如“这是现场仪式还是多个互动摊位？”因为两者会导致不同的高层信息组织。

**约束已明确但细节未知时：**把已知条件写入结构，未知值留作待定。例如时间地点已知但精确点位未定，保留时间地点的信息层并标出具体位置待补。不要为了未知日期、人数或奖品逐项新设标题。

## 七、证据边界与待确认问题

| 待确认问题 | 当前证据 | 为什么暂不能下结论 |
|---|---|---|
| 是否存在全校固定章节和顺序 | 五份活动策划案结构不一；项目决策也把固定模板视为开放事项 | 样本来自学生会，未覆盖所有学院和审核部门 |
| 哪些章节必须独立出现 | 时间、地点、参与对象等多次出现，但合并和分列方式不同 | 还没有学生会统一模板或审批意见作直接依据 |
| 迎新是否包含招新目标 | S05 写到吸纳新生骨干；S06 强调迎新以介绍组织为主并区分招新 | 可能是活动设计差异，也可能是资料口径差异，需要本次任务确认 |
| 应急预案何时必须单列 | S05 有单列应急预案，其他样本多在注意事项中处理要求 | 现有材料没有各活动必须设置预案的统一规定 |
| 预算和资源章节的具体格式 | 多份样本提供不同表格，有些数据口径存在疑点 | 具体审核模板及费用口径未提供 |
| 升旗仪式附件的完整结构 | 正文引用名单、站位图等附件 | 本次没有核对全部附件图像和版面 |
| 不同学院、不同类别的迁移范围 | 当前案例集中于东北大学学生会 2024—2026 年材料 | 缺少其他学校、学院、学术活动、竞赛和培训等样本 |

## 八、供未来 Skill 开发的归档建议

后续 Skill 的核心规则应围绕“先定高维信息层，再决定是否细分二级标题，最后放入执行细节”编写。知识条目按适用条件调用：先判断本次活动具有什么机制，再读取对应经验。Skill 不应把通用检查维度直接输出成固定目录。

### 用户确认的阶段要求（2026-10-10）

项目用户确认资料库包含约 98% 的常见工作案例，可作为本项目策划案经验的主要可信依据。案例为框架判断提供结构和颗粒度参照，实际框架仍根据本次活动选择内容。

**第一阶段验收标准：内容覆盖基本完整，注释使用合理。**讨论用框架可将相关信息层合并以降低理解负担；正式策划案再参照适用案例，将需独立呈现的一级标题拆分。活动背景、目的、时间、地点、参与人员等清晰标题不需要注释。“工作内容、工作安排、所需材料”等较宽泛标题可按需加一句内容方向，注释不推测细节；没有清楚且有用的说明时可以省略。

**第二阶段协作方式：逐模块专门询问，跨模块口述当轮分别确认。**AI 先询问当前主模块要写入的内容。用户可以口语、零散补充，无需具备策划案专业知识或按字段组织信息。AI 忠实保留用户提供的全部信息，只做必要的语言规范化，不臆想、扩展或补充未表达的内容。同一轮口述牵涉其他模块时，AI 先展示主模块，再按框架顺序展示受影响模块的相关内容供确认；这些模块之后轮到主模块时仍须专门询问。

全部模块完成专门询问和内容确认后，AI 必须先在对话框以便于阅读的普通形式展示完整稿件，并等待用户确认全文。用户提出修改后，重新展示修订后的完整稿供确认。用户确认后，才按 `交接规范/策划案格式交接规范.md` 生成 Markdown 交接稿。该文件是交接格式规范，不是最终策划案的保存位置。

以上是用户明确确认的产品要求，后续应进入 Skill 行为说明与相关知识资源；它不等于活动的具体事实，也不要求学生替 AI 做专业策划判断。

未来组织资源时，可把本文件作为框架设计方法参考，把[活动经验](activity-experience.md)、[内容颗粒度](content-granularity.md)和[注意事项](cautions.md)分别作为条件知识、层级细化指导和事实边界。归档内容供后续 Skill 开发使用；其建议与已经确认的项目决策、尚未确认的组织规则须保持区分。
