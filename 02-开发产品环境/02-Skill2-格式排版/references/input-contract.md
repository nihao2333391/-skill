# 输入契约

## 适用输入

输入必须是 UTF-8 Markdown 纯文字策划案。内容已经定稿，结构由上游撰写 Skill 明确表达。

## 主标题

主标题位于文件最前，使用一组成对标记。内部允许一行或多行，分行属于必须保留的信息。

```markdown
【主标题开始】
“师引前路，情满东大”
东北大学教师节主题活动策划案
【主标题结束】
```

开始、结束标记各出现一次。标记本身不进入 DOCX。

## 一级标题

一级标题独占一个自然段，使用 `##` 和连续的中文序号：

```markdown
## 一、活动背景及目的
```

一级标题从“一”开始，按正文顺序连续编号。

## 二级标题

二级标题独占一个自然段，使用 `###` 和连续的带括号中文序号：

```markdown
### （一）我和老师的100个故事
```

二级标题必须位于某个一级标题之后；进入新的一级标题后重新从“（一）”开始编号。

## 三级内容段落

三级内容使用阿拉伯数字、英文句点和完整段落：

```markdown
1.工作人员应提前到达现场，完成物资清点和设备检查，并向负责人报告准备情况。
```

- 一个编号对应一个自然段，可以包含多句话。
- 三级内容可以直接位于一级标题或二级标题下。
- 同一父级下从 `1.` 开始连续编号；进入新的一级或二级标题后重新编号。
- `1.` 后不添加空格。

## 普通正文

- 普通正文不添加对象标签。
- 一个自然段必须写在同一物理行中，由版面宽度产生的自动换行不写入 Markdown。
- 不同自然段之间至少保留一个空行；多个连续空行不表达额外意义。
- 非空行不得包含首尾空格。

## 落款

落款位于全文最后：

```markdown
【落款】
东北大学学生会
2026年9月7日
```

标记后必须恰好包含单位和日期两行。`【落款】` 不进入 DOCX。

## 拒绝条件

出现以下任一情况即停止：

- 主标题或落款标记缺失、重复、顺序错误。
- 正文没有从一级标题开始，或出现二级、三级跳级。
- 各级编号不连续。
- 使用未知 `#` 标题、未知 `【……】` 标记、代码围栏或项目符号列表。
- 出现 Markdown 表格、Markdown/HTML 图片或附件正文标记。
- 一个普通正文或标题被人工拆成多行。
- 落款后仍有其他内容。

错误报告应给出文件、行号、错误代码、问题文本和修正建议。程序不得自行猜测或修复。
