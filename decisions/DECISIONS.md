# 需求决策记录（交接时有效）

## 已确认的业务事实 / 产品决策

- D-01：策划案以活动组织和审核为目的，内容服务于真实业务；标题章节是组织业务内容的结果。
- D-02：学生会历年策划案通常存在较稳定的写法、章节和描述颗粒度，Skill 应学习并提炼可迁移范式。
- D-03：本次任务通常已有部分信息，例如目标、拟开展事项、上级要求、时间地点；信息可不全。
- D-04：过去同类案例为可选资源，不能作为本次 Skill 启动的硬依赖。
- D-05：用户提供部分本次信息后，Skill 先分析要覆盖的业务方面，再提出一级和必要的二级标题，以及每一部分需要确定的信息。
- D-06：框架经确认后，按一级标题逐模块补齐。可优先从与本次活动具体情况最密切的模块开始，之后逐一处理其余一级标题；每轮只处理当前模块。AI 整理后与用户对齐，得到确认再进入下一模块。用户看到当前模块的正常文章。
- D-07：内容最终完整后，第二模块依据明确的层级/顺序及样式要求生成可编辑 Word。
- D-08：跨模型复用是目标，设计应降低对模型特定能力的依赖；对各宿主的兼容性以实际测试为准。
- D-09：SDD 分阶段审核推进，重点先完成写作引导/框架生成，再完善排版。
- D-10：第一阶段的验收以内容覆盖基本完整、注释使用合理为依据。框架可合并相关信息层以降低理解负担；正式策划案应参照资料库的策划案一级标题，把需要独立呈现的内容拆开。无需给活动时间、地点、背景、目的、参与人员等含义清楚的标题添加注释；仅在“工作内容、工作安排、所需材料”等宽泛标题下，且简短内容方向确实有帮助时添加注释。注释不猜测未明确的活动细节；无法合理说明时可省略。
- D-11：第二阶段以已确认框架作为内容组织引导。学生可以用口语、零散补充的方式提供材料，无须先掌握策划案专业知识，也无须主动按章节或专业字段组织信息；Skill 将补充内容整理到框架对应部分，并根据新信息调整相关层级。遇到会改变事实或造成实质歧义的内容再作必要澄清。
- D-12：用户确认项目资料库覆盖约 98% 的常见工作案例，可作为本项目策划案惯例、结构与内容颗粒度的主要可信依据。历史案例仍需按本次活动需求选择适用内容。
- D-13：第二阶段按一级标题逐模块推进，可优先处理与本次活动具体情况最密切的模块。AI 每次先询问当前主模块要写什么；用户补充后，AI 忠实整理其全部信息，只作必要的语言规范化，不臆想、扩展或补充。AI 先展示当前主模块供确认；若这次口述还明确牵涉其他模块，则在同一回复中按框架顺序展示受影响模块已有内容供确认。此类关联确认不能代替该模块之后作为主模块时的专门询问。
- D-14：全部模块都完成专门询问和内容确认后，AI 必须先在对话框展示便于阅读的完整稿件，并等待用户确认全文。用户提出修改时，更新相应内容并重新展示完整稿，直到用户确认。确认后，按 `formatting-skill-workspace/策划案格式交接规范.md` 生成 Markdown 交接稿；该文件是交接格式规范，不是最终策划案的保存位置。

## 暂缓决定、但需要保留的接口原则

- O-01：层级信息采用 Markdown 标题、YAML、JSON、Agent 内部结构或混合形式承载。
- O-02：人类可读稿与程序化排版输入是否需要物理上两个文件。
- O-03：历史样本数量增加后采用何种知识检索或分类方式。
- O-04：DOCX 的生成库、操作系统及预览器选型。

这些开放事项由开发者先给出简单可验证方案，优先保持低认知负担和确定性。

## 当前不是第一期目标

- 可视化拖拽富文本编辑器、多人实时协同、复杂工作流审批、批量导入全校资料并自动训练模型。
- 让用户手工标注每个段落的 JSON 或频繁处理机器标签。
- 各类模型在所有平台百分之百兼容的承诺。
